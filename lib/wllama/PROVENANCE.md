# Vendored wllama library

`lib/wllama/src` is a copy of the TypeScript library from the wllama fork
(`https://github.com/aakash-chaddha/wllama`, commit `46af429`), plus the `decision` API added on top
of it, plus the prebuilt wasm binary. The page compiles it directly (`@wllama/wllama` is aliased to
`lib/wllama/src/index.ts`), so the repository is self-contained: `npm install && npm run dev` works
without the fork and without emscripten.

## What was changed relative to commit 46af429

Library (TypeScript, `src/`):

- `src/types/types.ts` - `DecisionRequest` / `DecisionResponse` / `DecisionField` / `DecisionCandidate`
  and `n_seq_decision` in `LoadModelParams`.
- `src/wllama.ts` - `createDecision(body)`, a typed pass-through to the server's `/v1/decision` body,
  and `n_seq_decision` in the load message.
- `src/glue/messages.ts`, `src/workers-code/generated.ts`, `src/wasm/{wllama.js,source-map.ts}` -
  generated by the build.

Engine (C++, in the fork, not in this directory; compiled into the wasm binary):

- `cpp/glue.hpp` - the `decs_req` / `decs_res` glue messages and the `n_seq_decision` load field.
- `cpp/wllama-context.h` - `action_decision()`, which posts a `SERVER_TASK_TYPE_DECISION` task to the
  same `server_context` the native llama-server uses; `n_seq_decision` handling forces the unified KV
  cache.
- `cpp/wllama.cpp` - the `decision` action dispatch.

Fork pin: `llama.cpp` at `89f5c5d27` (`parallel-decision-media` branch, thecodacus/llama.cpp fork)
plus `scripts/patches/0001-decision-candidates.patch`, which adds the `candidates` list to a scored
field in `tools/parallel-decision/decision-engine.cpp`.

## How to rebuild the wasm

The prebuilt binary is `src/wasm/wllama.wasm` (8.7 MB, memory64 + JSPI + WebGPU, built with emsdk
4.0.20 in docker). To rebuild it:

```bash
git clone https://github.com/aakash-chaddha/wllama
cd wllama
# the fork commit is not on a public remote yet: clone the local llama.cpp working copy
git clone /path/to/llama.cpp llama.cpp
git -C llama.cpp checkout 89f5c5d27
git -C llama.cpp apply ../scripts/patches/0001-decision-candidates.patch

SKIP_COMPAT=1 ./scripts/build_wasm.sh     # docker + emsdk, writes src/wasm/wllama.wasm + wllama.js
bash scripts/build_worker.sh              # embeds the new wasm glue into src/workers-code/generated.ts
```

Then refresh this copy:

```bash
cp wllama/src/wasm/{wllama.wasm,wllama.js,source-map.ts} Momos-1/lib/wllama/src/wasm/
cp wllama/src/{wllama.ts,types/types.ts,glue/messages.ts,workers-code/generated.ts} ...   # the TS side
```

`SKIP_COMPAT=1` skips the asyncify build for Firefox/Safari, which this cut does not ship.
